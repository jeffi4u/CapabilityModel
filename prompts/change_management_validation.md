# Capability Map Change Management Validation

This prompt provides the criteria and process for validating any proposed changes or additions to the Business Capability Map. 

When a change is proposed to the Capability Map, the proposal should be evaluated against the following validation rules:

## 1. Structural Integrity
* **Hierarchy Fit**: Does the new/changed capability fit neatly into an existing Domain and Sub-Domain? If not, does the proposal justify creating new ones?
* **Granularity**: Is the capability at the correct level of abstraction? (i.e., It should define *what* the business does, not *how* a process or system executes it.)

## 2. Naming Conventions
* **Action-Oriented Context**: Does the name summarize the business outcome (e.g., "Customer Record Management") clearly?
* **Uniqueness**: Does this capability unnecessarily duplicate an existing capability in another domain?

## 3. Data Integrity
* Ensure all changes correctly map to the expected CSV structure (`Domain`, `Sub-Domain`, `Capability`, `Tier`, etc.).

## 4. Map & Layout Impact Assessment
* Evaluate the visual impact of this change: how will this affect the dashboard breakdown, visualization sizes, and domain expanding/collapsing constraints?

*(Update these criteria as your business change approval processes evolve.)*
